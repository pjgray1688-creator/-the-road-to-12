# R12 Club — Apple App Privacy corrections

24 October 2026. Audited source base: deployed `ff8ec5f02727419991e3a4b8340ecb5432c48f64`. These are proposed App Store Connect corrections, not changes made in Apple's system. “Collected” follows Apple's off-device retention definition; this is a source/route audit, not a production database query or certification of provider settings.

## Scope finding that affects the answers

The Club native tab destinations are Reception, Daily checks, Inductions, Overview and More. However, `NativeAppConfiguration.club.scope` restricts native deep links, not all web navigation. `RouteWebScreen.swift` permits same-host HTTPS pages. The authenticated shared `/account` page contains Home/Training/Progress navigation, Training setup and My Gym links. Consequently ordinary users can reach personal R12 training, progress, Member Hub and related connections from Club. No scope restriction was added: that would require a separate reviewed change. Declarations must cover these reachable flows as well as Club staff operations. The synthetic reviewer view does not exempt real app collection.

Additional categories/purposes to correct:

- **Health — add for the currently reachable personal R12 health/progress/WHOOP flows**, with **Linked to User**, **App Functionality**, and **Product Personalization** where recovery/health inputs tailor training. Do not omit it merely because the native tab labels say Club. Health data's legal grounds still need owner confirmation.
- **Customer Support — add for identified support/privacy/deletion-request correspondence and response records**, App Functionality, Linked to User. Any optional-disclosure exemption must meet all Apple's criteria; it is not automatic for support.
- **Other Diagnostic Data — unresolved:** server/security/error logs require a retained-field and provider review. If collected beyond the immediate request, declare the applicable diagnostic subtype and linkage. Do not automatically select Crash Data or Performance Data for every log.
- **Payment Info — unresolved at the exact retained-field boundary:** hosted Stripe card entry outside the app with no developer access does not itself require this selection under Apple's stated exception. GoCardless bank/mandate references and any retained payment-method fields in reachable flows must be reviewed separately. No raw-card collection was found in Club code.
- **Photos or Videos — review optional real staff avatars (`avatar_url`, identity/station chooser) and support screenshots.** Progress-photo uploads remain unavailable, so do not declare them as an implemented feature. Rendering existing identifiable staff photos is evidence to investigate actual storage/provisioning; no new upload workflow was found. Do not infer exemption or collection solely from an unused image type.
- **Device ID — not established:** no IDFA, push registration or handset identifier collection found. Auth/session IDs belong under User ID; access-hardware IDs are separate.
- **Sensitive Info — not justified by DOB/age checks alone.** No biometric identity collection was found; visually checking ID does not establish retained biometric data.
- No Third-Party Advertising, Developer Advertising/Marketing or advertising measurement purpose was established. No tracking SDK, IDFA access or App Tracking Transparency request was found. **No Tracking is the source-based recommendation, conditional on the owner's vendor/configuration confirmation.**

## Providers and evidence limits

- **Supabase:** actual imports in `supabase-browser`, `supabase-server`, `supabase-club-repository`; Auth password login/sign-up/reset, account/session IDs, and scoped table/RPC operations. The primary data collector/storage provider. Schema/RLS/migrations establish intended enforcement, not proof that each migration is deployed. No production SQL or data inspection occurred.
- **Authentication:** current account UI uses Supabase email/password. No Google/Apple social sign-in button/provider call was found in that flow. Do not infer additional social-profile collection from Supabase's capabilities.
- **Stripe:** actual joining/commerce server providers create hosted checkout and store transaction/provider references. Production integration exists, but availability depends on role/configuration. Installation alone is not evidence of analytics or card storage. No Stripe settings or transactions changed.
- **GoCardless/PayPal:** relevant joining/payment adapters and completion routes exist. Their live enablement and exact retained payment fields remain a confirmation item. Do not represent every supported adapter as active for every transaction.
- **Vercel:** actual hosting confirmed through production deployment metadata. Package/layout inspection found no Vercel Web Analytics/Speed Insights SDK. Backend `console.warn/error` calls can reach hosting logs, but dashboard/drain settings, retention and identifiers were not inspected. Provider defaults must not be converted into asserted App Privacy answers.
- **Email:** configured application SMTP support and independent Supabase Auth mail; actual mail provider/retention remains owner verification. No email was sent. `peter@r12.live` is owner-confirmed monitored support; this does not certify any third-party provider agreement.
- **WHOOP:** personal routes are reachable through shared Account; connection tokens and normalized recovery data are stored when connected. No HealthKit native entitlement/API is present. WHOOP was not invoked.
- **Other external services:** Club barcode lookup can send a product barcode to Open Food Facts (`lib/club-barcode.ts`), not necessarily personal data. Remote avatar/product images can make requests to their actual hosts; assess configured personal-photo hosts, rather than label all product artwork as user content. Supplier adapter interfaces alone do not prove active Printify/supplier transmission of personal data.
- **Native:** SwiftUI, UIKit, WebKit, SafariServices, Foundation and OS logging; no third-party native package or crash/analytics SDK in Club project. Persistent WebKit storage maintains sessions. Boot-time API use only measures elapsed navigation time; Club now bundles reason `35F9.1`. This required-reason declaration is separate from App Store collection categories and does not claim that the web service collects no data.
