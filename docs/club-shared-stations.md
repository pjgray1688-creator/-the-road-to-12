# R12 Club shared stations

Personal R12 sessions remain persistent. A shared Club station is an explicit browser registration, not a screen-size guess. Managers register each venue device from **Club → More → Shared stations**. Registration is scoped to the current organisation and an active venue. The station secret is an HttpOnly, Secure-in-production, SameSite=Strict cookie; only its SHA-256 digest is stored in Postgres.

Each staff member creates a 4–6 digit Club PIN at **Club → Account**. The PIN is stored only as a PostgreSQL `pgcrypto` Blowfish/bcrypt hash (cost 12). Changing or disabling a PIN requires signing in with the current R12 password immediately beforehand. Five invalid attempts lock that person's PIN for five minutes across stations. A valid PIN is checked server-side and used to establish a fresh Supabase Auth magic-link session for that staff identity; it never unlocks the previous staff session.

Shared stations lock after five minutes without pointer, touch, keyboard, wheel, click, or navigation activity. The timeout can be changed with `R12_CLUB_STATION_TIMEOUT_MINUTES`. Only meaningful browser interaction renews the short-lived, HMAC-signed station/user binding; there is no background heartbeat, so a closed or suspended browser does not leave a long-lived station unlock. A lock signs out the current Supabase session but keeps the station registration. Staff chooser responses include only staff user IDs and first names and are served no-store. Club server routes and capabilities continue to resolve the current signed-in user; the station is never an actor.

Required server setting: `R12_CLUB_STATION_SESSION_SECRET`, a random secret of at least 32 bytes. Generate one with `openssl rand -base64 48` and add it as a server-only Vercel environment variable. Never use a `NEXT_PUBLIC_` name. The station migration is additive and must be reviewed/applied through the normal migration process before enabling stations. Do not put the station cookie or this signing secret into the future scanner/Windows application; scanner-device credentials are a separate trust boundary.
